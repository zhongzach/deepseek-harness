# Agent Note: SDK 启动输入归属

Status: implemented

[English](2026-09-12-sdk-startup-input-ownership.md) | 中文

## 问题

SDK 服务器可能在完整插件树加载结束前激活。若它此时消费 initialize，而插件树随后失败或替换了该服务器，待处理回调便可能在已释放上下文中继续运行，掩盖真正的启动失败。

## 决策

传输层先订阅启动器成功启动的 `appReady` 通知，再读取标准输入。只有 Loader 的嵌入环境使用可取消的稳定等待；直接进程内嵌入保留立即启动。资源释放会取消就绪监听，并等待启动工作结束，再关闭传输及其会话。Initialize 在接纳后仍校验当前路由。

SDK 快照控制器用正斜杠还原工作区占位符，保证 Windows 上 JSON 有效。POSIX 与 PowerShell 工具定义拥有各自的录制头部，不把真实平台差异规范化掉。

## 考虑过的替代方案

**仅在 initialize 内等待**会让已退役的服务器在就绪前消费请求。**启动前睡眠**不能证明加载成功。**忽略上下文或快照错误**会掩盖未完成启动并削弱回放依据。

## 影响

启动失败保留启动器的真实错误，不再被失活上下文的 RPC 错误掩盖。就绪前发出的请求缓存在输入流中，交给有效服务器处理。单元测试覆盖延迟提供方、服务替换与清理；PowerShell SDK 快照通过真实 CLI 验证截断与继续，不改变 SDK 默认长度上限策略。
