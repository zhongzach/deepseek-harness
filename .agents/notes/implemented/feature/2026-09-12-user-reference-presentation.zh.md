# Agent Note: 产品管理的用户引用展示

Status: implemented

[English](2026-09-12-user-reference-presentation.md) | 中文

## 问题

产品在输入框中展示本地化 skill（技能）标题，发送后却可能暴露序列化的调用 ID。为此替换整个用户消息渲染器会重复实现附件、复制操作与时间戳。改变序列化引用则会影响模型输入和历史回放。

## 决策

Chat 视图管理唯一的 `conversation.message.user-text` 链。获授权的渲染器通过可选的 `renderUserText` owner 回调，进入持久化用户和 steering（中途引导）节点以及即时提交回显。链接收原始文字、关联会话标签、已加载 skill 名称和可选的文件打开回调。不接管时保留原生渲染。附件和复制原文操作位于链外。稳定的 `data-user-message-bubble` 属性允许产品将样式限定到自身子内容。

共享的 `projectUserText` 匹配器接受可选的引用渲染器，传入类别、显示标签、精确匹配的 token 和去包装后的值；未匹配的普通文本保留内容与顺序。这既共享引用解析，也允许产品使用可读标题和可点击的文件胶囊。两个扩展均不改变 Session 事件、引用序列化、复制载荷或模型请求。

## 考虑过的替代方案

**序列化本地化标题，而非调用 ID。** 这改变的是执行而非展示，并让身份取决于可变标题。展示层可以解析标题而不改变调用权限。

**替换整个 keyed 用户渲染器。** 产品将承担图片、文件、复制操作和即时回显的责任。仅针对文字的链让这些原生行为保留唯一管理方。

**每次更新后改写渲染的 DOM。** 这绕过 slot 生命周期与 React 管理，存在历史回放后节点陈旧的风险，也无法与其他文本消费方共享匹配规则。

## 影响

产品可以本地化已发送引用和气泡样式，无需复制 Chat 内部实现。标题是否可用仍由产品元数据决定；标题不可用不能阻止展示原始引用。聚焦测试保留匹配、默认渲染、附件和复制行为。消费此能力的 WriterX 浏览器场景使用合成数据与本地模型 fixture（测试前置数据），检查发送后的本地化、精确模型输入、文件导航、刷新以及深浅色展示。
