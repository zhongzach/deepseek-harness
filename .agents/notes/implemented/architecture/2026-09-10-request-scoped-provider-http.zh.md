# Agent Note: 请求级提供方 HTTP 中间件

Status: implemented

[English](2026-09-10-request-scoped-provider-http.md) | 中文

## 问题

网关用量结算可能在 HTTP 响应头之后，通过 SSE（Server-Sent Events）元数据返回。提供方 SDK 可能丢弃这些元数据，导致部署方无法区分未确认占用与最终扣费。替换全局 fetch 还会拦截无关请求，丢失可靠的请求归属。

## 决策

LLM（大语言模型）事件接口声明 `llm/fetch`；pi-ai Chat Completions 适配器通过 SDK 的请求级 fetch 选项分派它。中间件接收不可变模型请求与实际 HTTP 操作，只委派一次，并负责所返回的响应流包装层。其他提供方协议保留原生传输。

HTTP 响应元数据继续使用 `llm/response-meta`；适配器不解释计费字段，也不把 SSE 记录冒充 HTTP 响应头。部署消费方负责回执验证、有界流处理、独立计费事件及持久化。事件不改变模型上下文或会话格式。

## 考虑过的替代方案

**替换全局 fetch** 会丢失传输作用域，并影响凭据、无关提供方及插件释放。**把网关专用字段加入适配器** 会将通用提供方实现与某个产品的计费规则耦合。**根据 token 统计推导扣费** 无法确认最终结算、占用或服务端策略快照。

## 影响

可信 Host 插件可观察后到的计费记录，无需共享可变的会话级请求状态。插件也会收到敏感 HTTP 输入，因此不得记录凭据或私有端点数据。流包装层必须保留背压及取消，限制元数据解析内存，并保留正常提供方输出及用量。事件本身不能恢复因断网或进程失败丢失的回执；网关账本仍是真源。
