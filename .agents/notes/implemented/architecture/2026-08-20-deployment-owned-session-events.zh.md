# Agent Note: 部署自有 Session 事件兼容

Status: implemented

[English](2026-08-20-deployment-owned-session-events.md) | 中文

## 问题

部署插件可以把产品自有、仅记日志的事件合并进 `SessionEventMap`，但仓库生成的 `KNOWN_SESSION_EVENT_TYPES` 无法包含声明在本仓库之外的类型。如果生产方尚未给一条必需记录写入 `ignorable: true`，同一部署组合在重建时也会拒绝该会话，即使已挂载的插件理解这条记录。

## 决定

**运行中的组合会显式注册每个部署自有事件类型。**`registerSessionEventType(type)` 把类型加入生成静态词汇旁的进程本地注册表，并返回由所属插件在卸载时调用的 disposer。写入事件的组合会在持久化层重建会话前挂载注册；未知且未注册的必需事件仍会拒绝。

**可移植的产品记录还会携带 `ignorable: true`。**`Session.append` 为仅记日志事件接受 `AppendIntent`，并为 surface 事件把它与 `SurfaceIntent` 组合。产品自有的信息记录使用该标记，使缺少该插件的其他同版本组合也能安全跳过记录。对于标记出现之前已经写入的记录，仍需显式注册。

**持久化生成器同时拥有两条兼容路径。**`gen-persistence-catalog` 会把静态事件集合、运行时注册表、注册函数和组合查询一起输出。生成文件绝不手工修补，因此目录新鲜度既保护事件名称，也保护运行时 API。

## 曾考虑的替代方案

- **把部署事件名称加入仓库生成集合**：会让提供方无关的运行时耦合到单个产品，也无法覆盖独立分发的插件。
- **只依靠 `ignorable`**：无法恢复该标记出现前已经写入的必需记录。
- **接受所有未知事件类型**：会静默丢弃一条可能关系到正确重建语义的记录。
- **完全根据已挂载组合构造已知词汇**：会让核心事件的可读性依赖插件选择；仓库生成的全量集合仍应作为同版本的稳定基线。

## 影响

同一产品组合可以重建旧的产品记录，而可移植的信息记录对原生组合仍然可读。注册是进程本地状态并随插件生命周期存在，因此每个部署自有类型都有明确所有者，并且必须在加载会话前完成注册。缺失注册会安全拒绝，而不是静默改变重建后的会话。生成器测试固定运行时 API，持久化目录的新鲜度同时固定两份生成产物。
