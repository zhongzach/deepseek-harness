# Agent Note: 基于已记录上下文的输出截断恢复

Status: implemented

[English](2026-09-12-output-limit-recovery.md) | 中文

## 问题

提供方的输出长度上限可能留下可用文字或不完整的工具参数，却不产生适配器错误。请求错误策略无法恢复这种终态，而原样重试可能重复昂贵输出，并让工具是否执行变得不清楚。

## 决策

Agent 事件接口在部分 Assistant 输出结算后、工具分派前提供 `agent/output-limit`。处理策略可保留或替换模型可见上下文，并要求在同一步中再次尝试。循环拒绝没有追加或替换上下文的重试，在回调后核对取消，并且绝不分派截断响应中的工具调用。没有策略时，max-tokens 保持原有终态含义。

恢复策略保留在循环之外。它负责部分输出的表示、请求预算和有界接续；普通网络错误继续使用独立的请求错误策略。既有 Session 事件保留原始提供方流及带来源的上下文变化，因此不需要新格式代次或伪造成功完成。

## 考虑过的替代方案

**无条件重试**会重复没有进展的相同请求。**把截断输出标为成功**会掩盖不完整工具并可能错误推进目标。**第二个 Agent 或任务队列**增加执行归属，却未解决部分输出留存。**轮次关闭后接续**会丢失原活动目标的执行区间。

## 影响

部署方可完成能够恢复的步骤，无需复制循环或改变默认 SDK 行为。无效恢复回调以 `INVALID_RECOVERY` 失败，不再花费一次模型请求。策略必须保留作者取消与文件保护，不得执行留存的工具片段。专项测试覆盖默认终止、同一步恢复、无上下文变化时拒绝、取消及未分派工具；端到端写作行为由部署场景验证。
