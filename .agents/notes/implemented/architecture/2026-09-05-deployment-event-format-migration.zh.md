# Agent Note: 跨 Session 格式世代的已校验部署事件

Status: implemented

[English](2026-09-05-deployment-event-format-migration.md) | 中文

## 问题

已发布的 WriterX 日志包含官方 v0 与 v1 冻结事件清单之外的信息型计费记录，部分记录早于 `ignorable` 标记。官方相邻迁移拒绝未知历史载荷是合理的，因为序列重映射无法推断未知载荷是否包含序列引用。仅保留当前事件注册表，仍会使这些既有会话在升级到 v2 后无法读取。

## 决定

产品通过低层格式包中的 `registerOpaqueSessionEvent` 显式注册不透明、仅记日志的事件。每项注册声明确切支持的格式世代并校验完整载荷，保证载荷不含 Session 序列引用；携带 surface 位置或来源序列的事件包络会被拒绝。冻结迁移清单继续负责官方事件，这个有限扩展则在外层事件位置变化时校验并保留已注册的信息记录。WriterX 计费插件只接受包含模型、扣费次数和可空余额的精确载荷，覆盖 v0、v1 和 v2。

当前格式注册表位于 Session 包中生成词汇之外，并对重叠所有者计数。目录在还原时获取注册快照。这既保留标记出现前的必需记录，也不使官方静态词汇依赖当前组合。注册生命周期跟随所属插件，产品会在打开持久化会话之前挂载计费插件。

本决定扩展[部署自有事件兼容](2026-08-20-deployment-owned-session-events.zh.md)，仅针对明确分类的产品信息调整未知事件拒绝策略。任意未知历史事件（包括未知 `ignorable` 事件）仍被拒绝。[不可变世代发布规则](2026-08-31-released-session-format-migrations.zh.md)保持不变：迁移只在未变的源文件旁独占创建带版本的后继文件。

## 曾考虑的替代方案

- 把 WriterX 名称写死在官方清单中，会把通用运行时耦合到单个产品，也无法校验独立部署插件的载荷。
- 信任所有已注册名称或 `ignorable` 标记，无法证明序列重映射安全。
- 改写旧文件以添加标记，会破坏原始产物，且仍未分类内部引用。
- 丢弃信息，会以丢失计费历史为代价使迁移成功。

## 影响

历史兼容要求在打开会话时存在产品校验器。测试通过真实提供方迁移 v0 和 v1 JSONL，保留无标记及有标记的计费记录，验证重映射后的位置与载荷，对比源文件 SHA-256，重新打开 v2，并证明未知类型、额外载荷字段或 surface 引用会被拒绝且不发布后继文件。所有者卸载测试覆盖两个注册表。通用运行时不会尝试修复损坏的产品历史。
